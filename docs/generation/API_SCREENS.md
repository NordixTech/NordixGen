# Declared browser operations, queries and forms

Clients, hooks, Explorer metadata and screens consume the same resolved connected HTTP operations. Module exports are not browser routes. Transport contracts contain ISO strings for dates, required nullable response properties, actual pagination/projection wrappers and only writable body fields. Each backend uses the same-origin `/api/backend/<backend>` proxy, which dispatches through its named private service binding. Multiple connections never silently send requests to another backend. JSON query values are JSON encoded, arrays use repeated parameters in their original order, and cancellation signals reach fetch.

Query keys start with `['nordixgen', backend, moduleId, operationId]`, followed by public/private identity scope and inputs. Mutation invalidation uses the same operation prefixes and only targets related declared reads on that backend. Pending/signed-out/insufficient sessions do not start protected reads. Forms, Explorer actions and queries use one frontend presentation predicate with current database permissions obtained from `/api/auth/iam/me`; backend/application enforcement remains authoritative. Changes to role or effective grants rotate the session query cache scope.

The shell reads Better Auth and keys its Query provider by a scalar pending/account/role identity. Every transition owns a fresh QueryClient. Disposing the previous client cancels its work and clears its cache; late completions cannot populate the next account's client. Public/private keys remain distinct, although all caches are discarded on account transitions. This deliberately favors isolation over retaining public cache hits. Zustand stores no sessions or remote records.

Automatic actions require one unambiguous resolved operation and sufficient known bindings. Update/delete bind the resolved entity identifier alias, rather than guessing the first path parameter. Required query inputs, additional path context and multiple candidate actions produce English warnings; their automatic action is omitted while every declared operation remains in typed clients and API Explorer. There is no new UI-binding configuration or invented workflow. A missing list has an explicit explanation, not a fabricated data request.

Form schemas/builders use each operation's HTTP inputs. Create defaults are displayed; absent clock defaults remain server-owned. Editing loads only writable fields. Nullable fields have an explicit null control. Integers, decimals, UUIDs, enum values, string constraints, JSON syntax and date values are validated before a typed request is built. Date/time controls use browser-local time and send UTC ISO strings. JSON text is parsed from the raw form values, preserving scalar strings; non-null JSON fields reject top-level null while nested JSON null remains valid. Declared query filters have an apply/validation step, and pagination resets on filter changes. No request or resolver is forced through an unrelated type assertion.

Evidence: CI compiles the generated clients and form builders, executes keys/gating/invalidation/cancellation with real TanStack Query core, and runs typed form mutations through generated Hono into isolated PostgreSQL. Tests include two Clean modules, another backend with a repeated operation name, missing actions, public/private reads, aliases, arrays/JSON, dates/nulls and ambiguous bindings. Local real Next.js builds and browser checks verify create/edit with persisted decimals, JSON, explicit null and local-date conversion; filtering/refetch; pending controls; and account change to a role that cannot read or edit prior records. Direct backend calls by that role return 403. The integrated commerce example additionally covers the connected product.

The maintained [commerce example](../../examples/full-stack-commerce/README.md) verifies fresh public-CLI generation, application compilation, Worker bundling, real PostgreSQL migrations/seeds, HTTP authorization, browser forms and account-cache isolation. Run `pnpm example:commerce` from the repository root; each run writes revision, environment and stage/behavior results into a new ignored `tmp/examples/full-stack-commerce/<id>/` directory. This verifies the supported local topology, not cloud deployment or every optional identity-provider journey.
